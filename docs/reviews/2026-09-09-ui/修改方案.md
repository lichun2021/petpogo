# PetPogo 页面回归与视觉修改方案

## 2. 社区：同时修复内容完整性和筛选一致性

**确定要修复的逻辑**

- 两个列表的滚动监听都进入 `_onScroll`，该方法只调用发现流 `loadMore()`。改为好友、发现各自分页，加载状态和错误也各自处理。
- 分类点击里用 `index == 1` 更新好友筛选，但好友实际是 Tab 0。纠正映射；切回“全部”必须清空好友请求里的旧 tag，不能只去掉本地过滤。
- 好友和发现卡片都调用 `_openViewer(i)`，该方法固定读取发现流原始列表。改为传入当前实际展示的列表和选中帖子 ID，再定位起始位置，避免点好友帖子或筛选结果时打开另一条。
- 搜索当前只查已加载内容且禁止分页。明确为“搜索已加载动态”，或在接口支持时改为服务端搜索和分页；不能让用户误以为检索了全部内容。
- 筛选后不足一屏却仍有下一页时，增加受控补页机制，避免没有可滚动距离而永远看不到后续匹配内容。

**布局与审美**

分类栏外层高度固定为 44，扣除上下内边距后只有 36，标签内部又有上下 14 的 padding。当前显示正常，但字号放大后空间容易不足。改为内容驱动的横向筛选栏，文字垂直居中、点击区域至少 44；不要通过缩小文字或裁剪消除问题。

保留双列内容卡片；筛选选中态采用品牌浅底和深色文字，减轻“搜索栏＋Tab 下划线＋实心分类按钮”的视觉竞争。减少卡片阴影，让图片和正文成为主角。列表末尾保留合理安全区，空态与失败态也能下拉刷新。

**验收**：好友/发现分别加载超过 20 条；狗→猫→全部→切 Tab 后结果正确；点击首条、中间条都打开同一帖子；最后一条可完全滚入可视区；长分类名、中文/英文和放大字体不裁切。

## 3. 萌宠圈：先核对失败链路，再改善图文阅读

当前真实图片已成功显示，因此本轮不能给出“图片不显示”的确定根因。现有实现仍有以下需要补齐的边界：

- `hasMedia` 只看 mediaType；类型缺失或未知时，即使有 URL 也会隐藏图片。应以接口契约为准，允许有效图片列表在类型缺失时兜底展示，同时避免把视频地址误当图片。
- `_stringList` 只接受数组。先采集脱敏的失败响应，再决定是否兼容字符串化数组或对象数组；不要猜测字段格式后盲目扩展。
- 单图路径只取 mediaUrls，不使用 coverUrl；视频则可能在没有封面时把视频文件交给图片解码器。按媒体类型区分原图、封面和视频地址。
- 错误组件目前只有破图图标。补充稳定占位、“图片加载失败”及重试；调试日志记录动态 ID、HTTP 状态和错误类别，避免记录鉴权信息。
- 如实际遇到过期签名或访问权限错误，由资源服务修正访问方式；前端重新获取有效地址，不能靠无限重试解决。

**建议的新布局**

宠物选择条 → 头像/名称/时间同一头部 → 正文 → 图片 → 轻量操作区。

当前头像占据整篇正文左侧宽度，正文又使用 18 号字并全文展开，长文将图片推到首屏底部。改为头部独立一行，正文与图片使用完整内容宽度；正文建议采用现有 14–16 号文字层级、舒适行高，长文默认约 4 行并提供“展开/收起”。字号调整后仍需验证辅助字号。

单图按原比例显示，限制极端长图的预览高度，并支持点击查看完整原图；多图按 2、4、9 张合理排列，避免两张图也硬排三列。当前单图固定 230 宽、1:1、cover，会裁掉非正方形原图。图片加载前后尺寸保持稳定，防止滚动跳动。

**验收**：纯文本、横图、竖图、长图、2/4/9 图、无视频封面、URL 失效、断网重试；切宠物不串内容；查看原图可看到完整画面。以真实失败样本确认最终根因后才能关闭“图片不显示”问题。

## 4. 我的宠物：一份性别信息，操作收进更多菜单

建议卡片结构：

```text
[头像] 咳咳爱爱                         ⋯
       布偶猫 · 公 · 已绝育（有数据时）
       2岁 · 4.5kg（有数据时）
──────────────────────────────────────
[设备图标] 毛毛的项圈                 ›
```

姓名行只保留姓名和更多入口；性别统一放在属性行，移除姓名旁的重复徽标。绝育信息单独规范化，避免在“公（已绝育）”之外再重复写一次。未知性别不猜测、空品种不出现开头分隔点。

三个并排图标改为一个至少 44 点击区域的更多按钮，菜单提供“编辑资料”“成员管理”“删除宠物”。删除保留现有确认流程，红色只出现在删除操作中。卡片主体保留清晰的资料入口，设备行保持关联设备入口。

属性行支持换行，长名字省略且详情可读完整名称；不固定卡片总高度。沿用页面 20、卡片内容 16、行间 8/12、圆角 18 的 token 体系，使姓名成为视觉中心。

**验收**：公/母/未知、已绝育/未绝育、长名/长品种、缺失年龄体重、未绑定设备、共享宠物；每张卡性别仅一次，编辑/成员/删除均可到达，窄屏无拥挤或溢出。

## 5. 宠物音乐：歌单改为自然高度列表

根因明确：横向列表仅高 100；卡片包含 72 高封面、6 间距、歌单名和数量两行。文字实际高度超过剩余 22，故出现底部 RenderFlex overflow。全局字体变化会放大这个缺陷。

推荐把“我的歌单”改为纵向紧凑列表：左侧封面、中间歌单名与曲目数、右侧进入箭头。行高由文字和内边距决定，长歌单名可显示两行。当前账号只有三个歌单，这种布局更易浏览，也不会把标题挤在小方块下面。数据较多时使用 SliverList，保持单一纵向滚动。

标题右侧改为“＋ 新建”按钮，点击区域至少 44；移除永久显示的绿色 NEW 标签。空歌单显示清晰的新建入口；加载失败显示重试，不能静默把网络错误当成“没有歌单”。

推荐分类保留插画，但减轻当前覆盖整张图的深棕遮罩，采用文字局部渐变保证可读性；分类标题和播放入口分开留白。未上线的“限免”及“音量设置”应隐藏或明确禁用，减少进入后才发现不可用的体验。

音乐页现有请求由 View 直接处理且存在吞错。实施时将相关请求状态放入 Controller，Repository 返回 Result，URL 迁入 ApiEndpoints；视图通过统一错误展示处理，遵循项目分层。

**验收**：0/1/3/20 个歌单、长名称、封面缺失/失败、请求失败、键盘弹起的新建面板；字号放大时无黄色溢出条；新建返回只刷新必要内容并保留浏览位置。

## 6. 整体审美判断

暖白背景、棕红品牌色和宠物插画方向可以保留。主要问题是信息层级失衡：宠物卡片过挤，萌宠圈文字过大且图片偏窄，音乐封面偏暗，二级页面标题有居中和左对齐混用，页面间左右边距也不一致。

统一规则：页面边距使用 AppSpacing.screenHorizontal，区块间距 sectionGap，内容间距 contentGap；卡片/控件使用 AppRadius；属性使用中性色，状态色只表达状态。减少粗体、描边和阴影同时叠加。统一二级页面标题的对齐与字号，视觉图标可小，实际点击范围不能跟着缩小。
