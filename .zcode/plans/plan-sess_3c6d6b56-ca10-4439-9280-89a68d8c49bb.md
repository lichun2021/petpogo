## 实施方案

### 1. AI 图像/语音分析增加必填 `account`
- 在 `AiAnalyzeController.analyzeVoice` 和 `analyzeImage` 中读取 `authControllerProvider.user?.account`。该字段是登录账号/手机号，不使用用户 ID、昵称或推送别名。
- 账号为空时直接进入明确错误状态，不调用上传和分析接口。
- 给 `AiRepository` 的 `uploadAndAnalyzeVoice`、`uploadAndAnalyzeImage`、`analyzeVoice`、`analyzeImage` 增加必填 `account` 参数。
- 在 `/voice/analyze` 与 `/image/analyze` 的 `FormData.fromMap` 中加入 `account: account`。
- 保持现有 `url`、可选 `pet_id`、OSS 上传和结果解析不变。

### 2. 统一马达指令 payload
- 从 `DeviceRepository.motorControl` 抽取可复用的纯 Dart payload 构造方法，继续使用现有协议：`motor_0`/`motor_1`，`direction=0/1/2`，`speed=0-100`。
- 原 Shadow 请求与新增 Agora Data Stream 共用该 payload，防止两套 JSON 漂移。
- 停止保持双马达 `direction=0, speed=0`，不改成另一种协议。

### 3. Agora Data Stream 生命周期
在 `RobotDevicePage` 中增加 `int? _motorStreamId` 及创建保护：
- `onJoinChannelSuccess` 后调用 `createDataStream`。
- 严格使用你确认的配置：`syncWithAudio: false, ordered: true`。
- 检查返回 stream ID，小于 0 视为失败。
- 所有 leave/release 路径以及 `onLeaveChannel` 都清空 stream ID；重新加入频道后重新创建。
- 通话判断使用 App 自身 `_agoraJoined`，不依赖远端视频码率。

### 4. 马达通道切换
重构 `_sendMotorControl`：
- 保留现有速度缩放和摇杆方向算法。
- `_agoraJoined == true` 时只使用 Agora Data Stream：payload → `jsonEncode` → UTF-8 `Uint8List` → `sendStreamMessage`。
- 校验消息不超过 512 字节。
- 未加入频道时保持现有 `DeviceRepository.motorControl` → Shadow/MQTT。
- 按你确认的策略：通话中 stream 未创建或发送失败时**不回退 MQTT**；仅写调试日志，不为高频控制逐条弹 Toast。

### 5. 控制频率与停止保障
- 保留现有摇杆 300ms 定时发送，低于 Agora 限流，无需新增节流器。
- 保留 pointer up/cancel 的立即停止。
- 主动 leave、暂停视频或打开媒体库前，如通话且 stream 可用，尽力发送一次停止后再离开，避免马达保持最后状态；不等待 ACK。

### 6. 测试与验证
- 新增纯 Dart 测试覆盖马达 payload：前进、后退、停止、双马达、非法 direction/speed、编码后长度。
- 覆盖 AI account 传递的可测试部分：账号来源、空账号阻止调用、multipart 含 `account`。
- 普通 `flutter test` 不实例化真实 Agora 原生引擎；真实消息收发用真机联调。
- 执行 `dart format`、修改文件静态分析、全部 `flutter test`、`git diff --check`。
- 真机验证：首次加入创建 stream、方向指令到达、松手停止、离开后恢复 Shadow、重新加入后创建新 stream。

## 不修改
- 不改 AI/Peer HTTP 或安全配置。
- 不改 Agora 音视频参数、Token、角色和远端视频判断。
- 不新增 MQTT 客户端，不等待设备 ACK。
- 不改变现有摇杆方向算法及速度缩放。
